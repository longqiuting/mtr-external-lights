# 水雾 → 原版雨丝质感 + 大幅加密（1.20.1）

日期：2026-11-09　范围：`v1.20.1`（`SprayParticle` + `RainSpray` + 粒子贴图），未提交 git。
取代 `report-2026-11-09-spray-self-particle.md` 里的贴图与参数（那份报告的 `flash.png` 圆点方案已作废）。

## 1. 贴图方案：从原版 rain.png 裁切（不是画出来的）

1.20.1 客户端 jar 里的 `assets/minecraft/textures/environment/rain.png` 是 **64×256**，结构是
**4 列 × 16 行共 64 格、每格 16×16** 的雨滴图集；原版 `WeatherRenderer` 拿它按格画竖向条带。
对 64 格逐格统计后确认：每格就是一根 **1 像素宽**的竖直雨丝，alpha 沿着长度方向渐变，颜色恒为
`#4667C3`。实测两个样本：

```
tile(0,0)  col 3  : FF FF FF FF FF FF FF F9 E9 D9 C8 B9 A7 98 86 00   （15 行，顶部实、尾部渐隐）
tile(1,11) col 8  : 00 00 00 00 00 00 00 00 86 98 A7 B9 C8 D9 E9 F4   （8 行，下亮上暗）
```

**做法**：裁三种原版雨丝（15 行长丝 / 8 行下亮 / 8 行中等），做成 16×16 的三张贴图
`spray.png`、`spray_b.png`、`spray_c.png`，`particles/spray.json` 里列三张，粒子构造时
`sprites.getSprite(random)` 随机取一根 —— 对应原版那 64 格图集本身的多样性。

唯一的人为改动是**横向柔化**：原版是 1 像素硬边，粒子缩到 0.08–0.18 格绘制时会闪，所以按
`0,0,0,0.22,0.85,0.85,0.22,0,0` 的权重把 1 像素剖面铺成 4 列（等效约 2 像素，占整格宽 1/8）。
**纵向 alpha 剖面逐像素照抄，未做任何重采样**。颜色取原版像素自身的 `#4667C3`。

## 2. 纵向拉伸：重写 buildGeometry

`SpriteBillboardParticle` 的 `getSize()` 一个值同时给宽高（正方形），只靠贴图里的细线长度不够，
所以 `SprayParticle` 重写 `buildGeometry(VertexConsumer, Camera, float)`：与
`BillboardParticle` 的实现逐行一致（同样的相机旋转、同样的顶点顺序与 UV、同样的
`getBrightness` / 颜色链），唯一差别是本地坐标的 `y` 先乘 `VERTICAL_STRETCH = 2.2`。
于是基础尺寸 0.08–0.18 的方块变成 **0.18–0.40 格高、约 0.02–0.05 格宽**的细丝。

## 3. 最终参数表

| 项 | 旧 | 新 |
|---|---|---|
| 粒子贴图 | `flash.png`（32×32 白色径向渐变，圆点） | `rain.png` 裁出的 3 根原版雨丝（16×16，`#4667C3`） |
| 每列车每 tick | 8 | **14** |
| 全局每 tick | 28 | **48** |
| 令牌桶 | 18/tick，容量 60（≈360/s） | **32/tick，容量 120（≈640/s）** |
| 每列车扫描车厢 | 8 | **12** |
| 寿命 | 10–18 tick | **8–14 tick** |
| 起始尺寸 | 0.12–0.28 | **0.08–0.18** |
| 纵向拉伸 | 无（等比方块） | **2.2×**（→ 视觉 0.18–0.40 格高） |
| 起始不透明度 | 0.45–0.60 | **0.35–0.55** |
| 水平初速扩散 | ±0.05 | **±0.08** |
| tint | (0.82, 0.90, 1.00) | **(1, 1, 1)**，颜色直接来自贴图 |
| 重力 / 阻尼 | 0 / 0.90 | 不变（故意不上重力，见 §5） |
| 诊断行 | spawned/skipped/cap/avgSize | 增加 `density=` |

`density=` 的定义：`本窗口 spawned / (48 × 100 tick)`，即**配额占用率**（分母是全局上限能给出的
最多个数）。抽签概率（25%–100%）与露天判定都会让它低于 1，读的时候要和 `skipped=`、`reason=`
一起看。格式 `density=0.187(897/4800)`。

## 4. 与原版雨丝的相似点

- **形状同源**：不是「像」，是同一批像素 —— 1 像素宽的竖条 + 尾部 alpha 渐变，剖面直接取自
  `rain.png` 的 64 格（`FF FF FF … 86`）。
- **长短不一**：原版图集里雨丝 4–15 像素不等，这里取 15/8/8 三根随机抽，屏幕上不会排成等长虚线。
- **颜色一致**：`#4667C3` 是原版雨滴自身的颜色，tint 改成白光，不再被 (0.82,0.90,1.00) 二次染色。
- **朝向一致**：竖丝沿相机竖直轴拉长（billboard），和原版竖条贴图一样永远立着。
- **屏幕宽度接近 1 像素**：0.02–0.05 格宽，配合 4 列抗锯齿，观感就是原版那种一像素细线。
- **一闪而过**：0.4–0.7 s 寿命，和原版雨滴一样不拖成雾带。

## 5. 有意保留的差异

原版雨滴靠重力急速下落；这条水雾是**列车高速行驶时从车体侧面卷起的水**，所以竖直初速仍是
0.01–0.02 的上浮 + 0.90 阻尼，`gravityStrength = 0`。加过重力试算：8–14 tick 内会下落约 0.8 格，
而水雾起点只有轨面上 0.30–1.05 格，尾巴会穿进道床 —— 所以不上重力，只把「雨丝」的形状和颜色
换过来。
