## 灯位解析的硬结论（重要，别再走错）

- 真实统计：**67 个资源包 / 318 个车辆定义**，313 个有 `LIGHTS` 部件，5 个完全没有。
- **`stage == LIGHTS` 不是头灯判据**：head/tail 命名组 225 个车型里只在 `ALWAYS_ON_LIGHTS`；
  `LIGHTS` 阶段主要是 `door_light*` / `roof_*` / `window_light` / `chenei` / `LCD8` / `tv`。
- 组名（带排除词）命中 **300/318 = 94.3%**，尾灯 289/318；失败的全是公交（无 head/tail 命名）。
- `render_condition` **不能判亮灭**，它只区分门灯开关（`DOOR_*_OPEN/CLOSED`）。
- 几何：bbmodel 里只有 40.4% 灯组落在车端 1 格内，中位数 1.84 格；存在一个 bbmodel 装多节车的情况，
  必须按 `spacing` 逐节算，不能按模型包围盒。

推荐判定顺序：显式声明 → 组名（排除表）→ `ALWAYS_ON_LIGHTS` + 端面几何 → 兜底估位。

## 环境铁律（已踩坑）

- 机器 16 GB。**同一时间只允许一个 MC 客户端**，否则 `mmap failed for G1 virtual space` / `0xC0000005`。
  启动一律走 `tools/mc-test-once.sh`：mkdir 锁 + 等待其它客户端 + 堆上限 10G + 超时 600s。
- **绝不杀非自己启动的进程**（旧版脚本会 kill 所有 java，已改）。
- 实机测试**只用存档「测试摄影专用」或其副本**，绝不碰「绫洛市」。
- 判断“是否崩溃”先看 `crash-reports`：`OutOfMemoryError: Java heap space` 是内存不够，不是模组 bug。

## 合规红线（重要）

RTE 是 **All Rights Reserved**：允许安装使用、录制传播，但**禁止复制、修改、再分发其源码或构建产物，也禁止用于二次开发**。

因此本项目：
- 不反编译复用 RTE 代码，不抄其类结构/常量/算法实现；
- 只参考**公开文档描述的行为**（如"灯位从模型读取""找不到就按车体尺寸估"这类功能级描述）；
- 具体实现全部基于 MTR 公开 API 自行设计（`DynamicTrainModel.partsInfo`、`RenderStage`、`BlockModelBase` 等）。

### 关于“真照亮”：两条路线的取舍

- **IRLights 式**：Java 端收集光源 + SSBO 上传 + GLSL 补丁注入 Iris 光影包，能出真正的体积光与遮挡。
  代价：要为每个光影包维护补丁，光影更新就得出新补丁，维护量随光影数量线性增长。
- **自建后处理**：拷贝深度 + 全屏 raymarch pass。原版/Sodium 下可行，但 Iris 下会与它的管线抢渲染目标。

结论（待用户拍板）：先把“光柱绑定 + 可编辑光束 + 导出 json”做扎实（这部分与光影无关，收益确定），
真照亮作为独立阶段评估，优先验证“原版 + Sodium”场景，Iris 场景再单独评估补丁方案。
