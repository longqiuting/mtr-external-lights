# 厦门 PSD-LCD 挂板（`mtrlte:psd_lcd_xiamen`）的面板几何

日期：2026-11-19 · 版本：`v1.20.1`

面板的**高度带 / 厚度 / 前后位置 / 每段宽度**不是估的，是从两处量出来的：

1. MTR 自己的屏蔽门顶板面板带（`docs/mtr-psd-top-research.md` §1.2 已用 `javap` 实测）；
2. 参考模组 `mtr_psd_lcd` 1.2.8（Fabric 1.19.2 / MTR 3.2.2）的模型与 BER（MIT，见 NOTICE §9）。

## 量到的数

| 量 | 来源 | 值 |
| --- | --- | --- |
| 面板高度带（块内 y） | MTR `RenderPSDTop` 面板矩阵：底边 `bottomPadding = 1.5px`、顶边 `8.5px` | **1.5 … 8.5 px**（16 分之几，高 **7px = 0.4375 格**） |
| 同一带的验证 | 参考模组 `models/block/psd_top_lcd14_groove_left_base.json`：插屏凹槽的上下唇在 `y 1.6` 与 `y 15.1` | 它自己那块是竖版 13.1px 高（见下） |
| BER 里画的屏幕 | `RenderPSDTop#drawGroovedScreen`：`drawTexture(..., y1 = 0.056, y2 = 0.874)`（y 从块顶往下量） | 13.09px 高 = **0.818 格**（`SCALE = 90`，即 1 格 = 90 单位） |
| 厚度 | 参考模组凹槽：箱体 `x 0…6`、槽底在 `x 4.4` | **1.6px（0.1 格）** |
| 前后位置 | 凹槽前面在 `x = 6` = 箱体朝外的那一面 | 屏幕面离方块外面 **1.6px（往里）** |
| 每段宽度 | MTR：`(leftBlocks + rightBlocks + 1) − 2 × sidePadding`，`sidePadding = 0.125/16` | **1 格 / 段**（整排两头各让 0.125px，肉眼不可见，代码里忽略） |

## 为什么高度取 7px，不是参考模组的 13.09px

参考模组那块 0.818 格高的是**它自己的竖版线路图**（MTR 顶板样式，朝 +X、沿门线 8px 宽），
和本模组的「厦门地铁 PIDS 版式」不是一回事：本模组的版式是按实拍
（`扫描全能王 2026-11-19 19.07.jpg`，6.91:1）与用户示意稿排的，全部布局常量都以「屏高 h」为单位。

- 7px / 格 ⇒ 每段 2.286:1；**3 段 = 6.857:1 ≈ 示意稿的 6.91:1**；
- 4 段 = **9.143:1**（MTR 文档里「4 格 → aspect 9.11」正是同一组比例）；
- 若取 0.818 格，4 段只有 4.89:1，比设计稿还窄 —— 左卡片和右侧一组会叠在一起，不可用。

## 模型来历（2026-11-19 21:40 之后）

用户第三次纠正后，模型改成**直接沿用参考模组的嵌屏吊板模型**（MIT），不再手写：

| 本模组元素 | 参考模组对应元素 | from → to（本模组，16 分之格） |
| --- | --- | --- |
| `TopSlab` | 顶板 `[0,15.5,8] → [6,16,16]` | `[0,15.5,0] → [16,16,6]` |
| `BottomBand` | 下带 `[0,1,8] → [6,1.6,16]` | `[0,1,0] → [16,1.5,6]` |
| `Body` | 箱体 `[0,1.6,8] → [6,15.5,16]`（只有背面） | `[0,1.5,1.6] → [16,15.5,6]` |
| `ScreenPlane` | 槽底 `[4.4,1.6,8] → [4.4,15.5,16]`（零厚度面） | **`[0,1.5,1.6] → [16,8.5,1.6]`** |
| `FrontSkinUpper` | 上唇 `[4.4,15.1,8] → [6,15.5,16]` + 前面板 | `[0,8.5,0] → [16,15.5,1.6]` |
| `BottomStep` | 台阶 `[0,0,8] → [5,1,16]` | `[0,0,1] → [16,1,6]` |
| `BevelLower` | `[5,0,8] → [5.7654,1,16]`（origin `[5,0,8]`, z, +22.5°） | `[0,0,0.2346] → [16,1,1]`（origin `[0,0,1]`, x, +22.5°） |
| `BevelUpper` | `[5,0.2346,8] → [6,1,16]`（origin `[6,1,8]`, z, −22.5°） | `[0,0.2346,0] → [16,1,1]`（origin `[0,1,0]`, x, −22.5°） |

**两处必要的差异**（原文件不能直接丢进去用的原因）：

1. **轴**：参考模型是**竖版屏蔽门面板** —— 法线 +X、沿门线只有 8px、整块高 13.9px、屏幕窗口
   13.1px 高 × 8px 宽（1.22:1，竖的）。本模组是**横向吊板** —— 法线 −Z、沿墙 16px、屏幕带 7px。
   所以厚度轴 `x → z`、铺开轴 `z → x`，屏幕带按 MTR 顶板面板的 7px 重排（与 blockstate 的
   `y` 旋转是同一套右手系：`x 0…16 / y 1.5…8.5 / z 1.6`）。
2. **窗口带**：参考模型窗口是 `y 1.6…15.1`（它自己那块竖屏），本模组必须落在 `y 1.5…8.5`，
   否则和 `PsdLcdLayout`、BER、位图宽高比全都对不上。

## 屏幕四边形（BER）

`PsdLcdLayout#windowQuad(facing, segments)` 直接算出世界坐标的四个角，顺序
**左上 → 左下 → 右下 → 右上**，正好对上贴图的 `(0,0) (0,1) (1,1) (1,0)`：

```
facing=north（3 段，anchor 那一格最小角为原点）
  左上 (1.000, 0.531, 0.099)   左下 (1.000, 0.094, 0.099)
  右下 (-2.000, 0.094, 0.099)  右上 (-2.000, 0.531, 0.099)
  y = 0.094…0.531 格 = 1.5…8.5px   z = 1.584px（模型面 1.6px 之前）
```

四个朝向的法线 / blockstate `y` / 顶点表用 `node v1.20.1/tools/psd-lcd-facing-check.js` 打印，
位图宽高比与「首行不是黑边」用 `node v1.20.1/tools/psd-lcd-fit-check.js` 断言。

## 2026-11-19 21:40 修掉的三件事

1. **朝向**：放置固定取 `getHorizontalPlayerFacing().getOpposite()` —— 屏幕永远面朝放置的玩家
   （以前按「点哪面朝哪面」，站在正面放会得到背对着你的屏）。
2. **模型 / 贴图**：改用参考模组的嵌屏吊板模型 + 它的 `black.png`（见上节、NOTICE §9）。
3. **绘制**：删掉「广告层 / 滚动标语层」两个额外的 quad 与 MC 文字层，全部并进一张位图；
   四边形四顶点严格等于窗口矩形。旧版把屏幕**中线** y=5px 当成四边形原点再 `rotZ(180)`，
   7px 高的画面就从 y=5px 挂到 y=−2px —— 窗口上半截露黑、内容整体偏下、还溢出到吊板下面。
   （**广告区本身不是这一层**：它一直要占位，只是改成画在同一张位图里，见下一节。）

## 版式：按设计稿归一化比例（2026-11-19 重排）

上一轮把「广告区」当成多余层删掉了，结果右侧一片蓝到底、编组行被挤到最右边并压在当前站上。
现在版式**照设计稿 `厦门地铁PSD-LCD示意.png`（5383×779 = 6.910:1）逐像素量出来的比例**摆：

- **x 一律按「占屏宽的比例」**（0 = 左缘、1 = 右缘）；
- **y 和所有尺寸（字高 / 卡片宽高 / 描边）按「占排版高 h 的比例」**。

这样屏再宽（4 段 9.14:1、13 段 29.7:1）也只有分栏位置被拉开，字和卡片不会被拉成胖头鱼。

两条与「肉眼估」不同的地方，都是量出来的：

1. **广告区左缘是 0.7197**，不是 0.79 —— 设计稿蓝色内容区到 x=3873px 为止、洋红从 3874px 开始
   （5383px 宽的 0.7197）。0.79 这条线落在广告区**里面**；`psd-lcd-fit-check.js` 两条都断言。
2. **编组注记**设计稿从 0.3158（车头底下）起笔，但那一块正好压在第二行「分钟 / min」下面，
   照抄会两行字叠在一起，所以代码里从 0.3950（`分钟` 列右边）起笔。

编组行的两条规则：

- **车头独立占位、尺寸不缩**（按自然卡片高 0.224h×1.035 算），卡片右缘对齐 0.6894；
- 节距与卡片宽同比例（设计稿 0.0068 ÷ 0.0656 = 0.104），所以 13 节时**只缩卡片宽**：
  `cw = (槽宽 − 车头宽) / (n + (2n−1)·0.104)`，卡片高 `cw × 1024/2144` 永远不超过行高 0.2378h。

广告区：同一张位图里的一块，**不是另一个 quad**。内容优先铺厦门 PIDS 那套广告图
（`PidsXiamenSettings.applyAdOverride(entity.getAds())` + `advertisementIndex` 轮播，
`PsdLcdAssets#ad(Identifier)` 把 PNG 读成 `BufferedImage`，按 cover 铺满），
拿不到图就画设计稿那种洋红块 + 居中「广告位」。

## 用法

挂在**顶板下沿那一格**（门头高度），面板就贴在吊顶下沿、和 MTR 顶板箱体的显示带同一高度，
实拍就是这样。`PsdLcdRenderer` 把整张位图（每段 1040px 宽、455px 高）贴到窗口矩形上。
