# 1.19.2「光散射（sss）不出光」— 定位与修复

日期：2026-11-14　范围：**只改 `v1.19.2`**（另加一个 `tools/` 诊断工具，不进 jar）

## 结论

1.19.2 上 `dev.js.mtrheadlight.compat.Matrices#columnMajor` **每一帧都抛
`BufferUnderflowException`**，而它被 `ScatterPass.rigid()` 用在 `render()` 里 ——
于是 `render()` 每帧整体抛出去、`frames` 永远是 0，**整条 pass 一笔都没画**。
表面照亮和空气光都来自这一条 pass，所以「什么都看不到」。

修掉之后同一套着色器与绘制路径在真实驱动上正常出光（离线验证：380 / 4096 像素被点亮，
`uTest=1` 的纯红探针 4096 / 4096）。

## 根因（含证据，可复现）

### 1. `Matrix4f.writeColumnMajor` 在 1.19.2 是「绝对下标写」

```text
javap: net.minecraft.util.math.Matrix4f#writeColumnMajor(FloatBuffer)
   invokestatic pack(int,int)
   FloatBuffer.put(int, float)      ← 绝对下标写，position 不动
```

`Matrices.columnMajor` 原来的写法是 `writeColumnMajor(buffer); buffer.flip(); buffer.get(out);`。
写完 position 仍是 0，`flip()` 把 limit 也设成 0 → `get(float[16])` 抛
`BufferUnderflowException`。离线用 1.19.2 的 `Matrix4f` 直接调用那份 `columnMajor`
即可复现：`THROWS java.nio.BufferUnderflowException`。

调用链：`render()` → `viewMatrix()` → `rigid()`（第一个候选就调它）→ 抛。
`render()` 外面是 `catch (Throwable)`，所以现象是安静的：一帧一行
`[lte] scatter: pass failed`，`frames=0`，画面无变化。

1.20.1 / 1.19.4 用 joml，没有这个 API 形状；1.18.2 走 `clientgui.Matrix4f`，所以三版都没踩到。

### 2. 顺带发现的第二个 1.19.2 差异（**不是**不出光的原因）

`Matrix4f#invert()` 在 1.19.2 是旧 Blaze3D 那份实现：

| 输入 | `|inv*A − I|` |
|---|---|
| 纯旋转 / 平移（仿射） | `1.8e-7` ✔ |
| `projection * view` | `0.958`（实测 `mcInv * vp = 0.0132 * I`，差一个统一缩放） |

统一缩放在本 pass 里恰好无害（着色器里的 `rd` 归一化、`tHit` 用 `xyz/w`），
所以它**不是**不出光的原因；但它会让「逆矩阵对不对」这个判据永远失效 ——
而这次修复正好要加这一格诊断，所以一并换成精确求逆（`|inv*vp − I| = 7.1e-15`）。

原版从不对投影矩阵求逆，1.19.2 上线至今没人踩过这个限制。

## 逐条核对：1.19.2 与 1.20.1 的 Shader / FBO 路径

| 关注点 | 结论 | 依据 |
|---|---|---|
| 自定义 core shader 能否加载 | **能**。`Shader(ResourceFactory, String, VertexFormat)` 与 1.20.1 的 `ShaderProgram` 同签名，资源 id 重写照样生效 | javap + 离线加载：`LOAD OK programRef=3`，`uInvViewProj=5 uMaxRay=54 uCone=2 uSurface=55 uCount=3 uTest=56 uDebug=4`，`uLightPos=38 uLightDir=22 uLightColor=6` |
| `light_scatter.json` 字段是否要改 | **不用**。`attributes:["Position"]` 在 1.19.2 走 `JsonHelper.asString`（接受裸字符串）；`samplers:[{name}]`、`uniforms` 的 `matrix4x4/float/int` 全支持 | 构造器字节码 + 离线加载成功 |
| `RenderSystem.setShader(() -> shader)` | 用法正确；1.19.2 的 `drawWithShader` 内部 `getShader()` 取的就是它 | `BufferRenderer.drawWithShader` 字节码 |
| 全屏四边形收尾 | 做法正确：`begin(...)` → 4×`vertex().next()` → `endNullable()` → `drawWithShader`；1.19.2 内部会 `upload` 后 `release` | 同上；离线绘制无 GL 错误 |
| 采样器绑定 | 1.19.2 在 `VertexBuffer.drawInternal` 里用 `RenderSystem.getShaderTexture(i)` → `addSampler("Sampler"+i, …)`，正好对上 `setShaderTexture(0/1)`；`Sampler0→unit 0`、`Sampler1→unit 1` | 字节码 + 离线实测 |
| 深度/颜色附件访问 | `Framebuffer#getDepthAttachment()/getColorAttachment()` 在 1.19.2 存在；`DepthCopy`/`ColorCopy` 与 1.20.1 逐字节相同（纯 blit，不需要 `glCopyImageSubData`），**无需降级** | `javap` + 文件 diff 为空 |
| 视图矩阵兜底（`MatrixStack` + `RotationAxis` 替身） | 与 joml 的 `Rx(pitch)·Ry(yaw+180)` 数值一致（本机核对） | 离线矩阵数值 |
| 混合状态 | 1.19.2 的 `Shader` 带 `GlBlendState`，缺省是 `ONE/ZERO`（等价 replace），与 `disableBlend()` 的意图一致，无需在 json 里写 `blend` | `GlBlendState()` 构造器常量 |

## 改动清单

### `v1.19.2/src/main/java/dev/js/mtrheadlight/compat/Matrices.java`
- `columnMajor()`：改为按绝对下标读（不再 `flip()`），并在 javadoc 里写清原因。
- 新增 `invert(Matrix4f src, Matrix4f dst)`：列主序标准余子式展开的精确 4×4 求逆。
- 新增 `inverseError(Matrix4f a, Matrix4f b)`：`|a*b − I|` 的最大元素偏差，供周期行判据。

### `v1.19.2/src/main/java/dev/js/mtrheadlight/sss/ScatterPass.java`
- 深度重建矩阵改用 `Matrices.invert(VIEW_PROJ, INVERSE)`，并记录 `inverseOk/inverseErr`。
- `rigid()` 兜住 `Throwable`（辅助判据不该有能力关掉 pass），失败只报一次 ERROR。
- **5 秒周期行改成一行定位格式**（无条件、与任何闸门无关）：

```text
[lte] scatter: frames=300 lights=4 program=ok depth=1920x1080 ok color=1920x1080 ok litPx≈15234
               inverse=ok blend=replace matrix=context calls=301 maxLights=4 avgMs=0.42
               surface=on debug=off pack=false reason=ok
[lte] scatter light0: pos=(…) dir=(…) rgb=(…) power=… radius=… beam=… coneDeg=20.0/56.6 depthErr=ok
```

`frames=0` 时 `reason=` 就是答案；`inverse=` 取 `ok | bad(0.958) | singular | none`。
`/mtr_lte scatter status` 同步加 `inverse=`。

### `tools/ScatterPipelineCheck192.java`（新增，诊断工具，不在任何 sourceSet 里）
不用启动游戏即可离线验证这条链：用 Minecraft 自己的 `Shader` 加载器加载
`assets/mtrlte/shaders/core/light_scatter.*`（含同一套资源 id 重写），再把
`ScatterPass` 的矩阵链 + 一盏灯喂给它，对合成的深度斜坡与纯色场景绘制并回读：

```text
java -cp "<mc1.19.2 mapped>;<lwjgl+libs>;v1.19.2/build/classes/java/main" ScatterPipelineCheck192 \
     v1.19.2/src/main/resources/assets [fixed|legacy|ident|test|dbg]
```

实测：`fixed` → `|inv*vp−I|=7.1e-15`，380/4096 像素被点亮 → `RESULT: light is drawn`；
`ident`（单位逆矩阵做对照）→ 0 像素；`test`（`uTest=1`）→ 4096/4096 纯红。
