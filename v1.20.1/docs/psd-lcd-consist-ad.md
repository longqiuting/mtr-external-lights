## 1. 可用宽度按「面板实际段数」算

### 段数

```java
segments = max(1, round(位图宽 / 1040))        // 1040 = 520(PX_PER_BLOCK) × 2(BITMAP_SCALE)
```

1 段 = 1040×455、2 段 = 2080×455、3 段 = 3120×455（高永远是 455 = 7px 窗口 × 65）。
**编组行的每一个数都从这个实际像素宽减出来，没有一处再用设计稿的 6.91:1。**

### 内容盒高（只管字号 / 行高，不参与可用宽度）

```
h = min(屏高, 屏宽 / 3.9)        // PsdLcdPainter.MIN_CONTENT_ASPECT = 3.9
```

* 3 段及以上（≥ 6.86:1）→ `h = 屏高`，一个像素都不留边；
* 2 段（4.57:1）→ `h = 屏高`；
* 1 段（2.29:1）→ `h = 屏宽/3.9 = 266.7px`，上下各留 94px 蓝边。

为什么不再按设计稿 6.91:1 把内容压成一条：那样 1 段的内容盒只有 150px 高（屏高的 33%），
字小到看不清、上下各留 1/3 屏空的蓝边；而直接用整屏高时列宽只有设计稿的 1/3，站名 / 徽标 /
编号全被压到 62% 以下再截断。3.9:1 是「列还能放下名义字号」的那个极限（1 段屏上最紧的
`6号线` 徽标还有 ~100% 余量）。

### 编组行可用宽度

```
left    = max(CAR_ROW_X0, CAR_ROW_GUARD_X) × 屏宽     // = 0.4392 × W
right   = CAR_ROW_X1 × 屏宽                          // = 0.6894 × W
ch      = min(CAR_W·h·(1024/2144), 行高·h)           // 卡片高：固定，与节数无关
cwNat   = ch ÷ (1024/2144)
noseW   = ch × 1.035 × (74/180)
avail   = right − left − noseW                       // 车头之外能用的宽度
cw      = min(cwNat, avail / (n × 1.1))              // 1.1 = 1 + 间隙比 0.1
```

`cw = avail/(n·1.1)` 时整行正好等于 `avail` ⇒ 车头左缘落在 `left`、末卡右缘落在 `right`，
**任何节数都不会越界、不会互相压**（这是恒等式，不是调出来的）。

### 守卫线为什么从 0.388 挪到 0.4392

「已到站 / 即将进站」左对齐写在 `NUM_COL_L 0.3051` 起、一直铺到 `NUM_COL_R 0.4322`；这一档
没有数字也没有单位，整块都归它。而第二行的状态文案 y 带是 `0.561…0.738`，正落在编组行的
`0.449…0.687` 里 —— 行槽只要从 0.3158 起就一定会压掉「站」字（实机截图：第 2 行「即将进站」
右半被车头盖住）。所以守卫线取 `NUM_COL_R + 0.007 = 0.4392`，**不随内容变**（倒计时从「3」
跳到「已到站」时整行不能平移）。

## 2. 压缩 / 降级规则（卡片高不变，先压宽、再压间距，最后少画几节）

1. **只压宽**：卡片高 `ch` 由行高和自然比例定死，与节数无关；宽度方向压缩，间隙按同一比例缩
   （`gap = cw × 0.1`）；
2. **压到下限**：`cw < cwNat × 0.32` 时不再往窄里压（再压就是一条竖线）；
3. **降级**：把 `cw` 锁在 `cwNat × 0.32`，算还能放几节
   ```
   k = floor((avail − cw×0.55 − cw×0.1) / (cw×1.1))   // 0.55 = 尾部「…」的占位槽
   ```
   画前 `k` 节 + 尾部三个白点（「…」），整块仍然右缘贴 `CAR_ROW_X1`。

实测表（位图 px，段数 × 节数）：

| 段数 | 4 节 | 6 节 | 8 节 | 行槽 |
|---|---|---|---|---|
| 1 段 1040×455 | 4 节（43%） | **4 节 + …**（32%） | 4 节 + … | 234.8px |
| 2 段 2080×455 | 4 节（51%） | 6 节（34%） | 5 节 + … | 477.0px |
| 3 段 3120×455 | 4 节（79%） | 6 节（52%） | 8 节（39%） | 737.3px |
| 4 段 4160×455 | 4 节（100%） | 6 节（71%） | 8 节（53%） | 997.5px |

（括号里是卡片宽 / 自然宽。所以「1 段 + 6 节」是唯一会少画的常见工况 —— 正是用户说的
「段数少到实在放不下才减少显示节数」。）

「…」画的是三个圆点而不是 `U+2026`：`SimHei` / 资源包字体经常缺这个码位（缺了就是白方块），
而且这个字形的墨迹高只有几个小点，按墨迹高反推字号会算出巨大的字。圆点是纯几何，永远一样。

## 3. 广告：非等比拉伸，四边严格夹在区内

* **允许非等比**：整张广告图拉伸到恰好等于区域，不再按 cover 保比例（保比例时宽图裁上下、
  高图裁左右，屏幕上看着就像「广告跑出了它那块」）。
* **三重夹紧**：
  * 目标矩形 = `adRegion(W,H)` = `{round(0.7197·W), 0, W, H}`（整数像素）；
  * 源 UV = `adSourceUv()` = `{0,0,1,1}`，写之前显式夹到 0…1；
  * 画的时候再套一层同矩形的 `clip`。
* **没有广告图**：整块留空（不画占位色块 / 占位文字）。

## 4. 断言（126 条，`preview-segments.sh` 全绿）

每个（段数 × 节数）都验：

* 编组行包围盒 `x ∈ [0.4392·W, 0.6894·W]`，`< 广告区左缘`；
* 相邻卡片间隙 = `cw×0.1`（一张都不重叠），末卡 / 「…」右缘 = 行右缘；
* `显示节数 ≤ 声明节数`，降级时 `shown < declared` 且尾部有「…」；
* 卡片高与节数无关；
* 「已到站」（第 1 行）与「即将进站」（第 2 行）的**墨迹包围盒**与编组行包围盒
  **0 像素重叠**（`textBox` 与 `line()` 同一份算术），且不出 `NUM_COL_R`；
* 「当前站」文字在编组行上方；
* 广告区 = 整屏高、右缘贴位图右缘、左缘 = `round(0.7197·W)`（0 误差）；
* 广告区内 441 个采样点**没有底色**（铺满、没留边）；左边界外侧 6 列**全是底色**（没溢出）；
* 广告四角都是广告色；UV 四项都在 0…1；
* 广告四边形 ⊆ 屏幕窗口四边形（整块 / 剪后 × 1/2/3 段，0 误差）。
